This page answers the most common questions server admins have about setting up and using rLogin. If your question is not answered here, join the [Pyrelight Discord](https://discord.gg/pyrelight) for community support.

<AccordionGroup>
  <Accordion title="What is the difference between premium and non-premium (cracked) players?">
    A **premium player** owns an official Minecraft account purchased through Mojang or Microsoft. When a premium player joins your server, rLogin verifies their identity by contacting Mojang's session servers — no password is needed on your server.

    A **non-premium (cracked) player** does not own an official account and connects using a third-party or offline client. Because Mojang cannot verify their identity, rLogin requires them to register a password with `/register <password> <confirmPassword>` and log in with `/login <password>` on each session.

    rLogin lets both types of players coexist on the same server, handling each authentication method automatically. See [Premium Authentication](/features/premium-auth) and [Cracked Authentication](/features/cracked-auth) for more details.
  </Accordion>

  <Accordion title="Do premium players need to register or log in?">
    No. Premium players are authenticated automatically by rLogin using Mojang's session servers the moment they connect. They do not need to run `/register` or `/login` at all — rLogin handles their verification in the background.

    <Note>
      If a premium player is being asked for a password, your `auth-mode` setting or Mojang session server connectivity may be misconfigured. See the [Troubleshooting](/help/troubleshooting) guide for steps to fix this.
    </Note>
  </Accordion>

  <Accordion title="A player forgot their password — how do I help them?">
    As a server administrator, you can delete their registered account so they can start fresh. Run the following command from your console or in-game, using the player's exact username:

    ```text
    /rlogin unregister <player>
    ```

    After you run this command, the player's old password is permanently removed from the database. They can then register a new password with `/register` on their next login.

    <Warning>
      This action is irreversible. Make sure you are helping the correct player before unregistering their account.
    </Warning>
  </Accordion>

  <Accordion title="Can I use rLogin on a BungeeCord or Velocity network?">
    Yes. rLogin supports proxy network setups. Install rLogin on every backend Spigot, Paper, or Purpur server in your network, then configure each server's `auth-mode` to match your overall setup.

    <Steps>
      <Step title="Install on each backend server">
        Place the rLogin `.jar` in the `plugins/` folder of every backend server in your network.
      </Step>
      <Step title="Set auth-mode">
        Open `plugins/rLogin/config.yml` on each backend server and set `auth-mode` to `auto` for mixed premium/cracked networks:

        ```yaml
        auth-mode: auto
        ```

        Refer to the [configuration guide](/configuration/config-file) for all available `auth-mode` values.
      </Step>
      <Step title="Restart each backend server">
        Restart every backend server to apply the changes.
      </Step>
    </Steps>

    <Note>
      rLogin runs on the backend servers only — not on the proxy itself. Authentication is handled per-backend by rLogin before players are allowed to interact.
    </Note>
  </Accordion>

  <Accordion title="Does rLogin work with 1.19+ chat signing?">
    Yes. rLogin does not interfere with the chat signing features introduced in Minecraft 1.19. Players send and receive signed chat messages as normal. rLogin only intercepts authentication events — it does not modify the chat pipeline.
  </Accordion>

  <Accordion title="Can premium and cracked players have the same username?">
    By default, no. When `prevent-username-steal: true` is set in `config.yml` (the default), rLogin checks whether a connecting non-premium player's username belongs to a real premium Mojang account. If it does, the non-premium player is blocked from joining with that name.

    This prevents cracked players from impersonating premium accounts on your server. You can disable this protection by setting `prevent-username-steal: false`, but doing so is strongly discouraged.

    ```yaml
    # config.yml
    prevent-username-steal: true
    ```

    For more details on how this protection works, see the [Security features](/features/security) page.
  </Accordion>

  <Accordion title="How do I switch from online-mode to offline-mode (or vice versa)?">
    Switching authentication modes requires changes in two places:

    <Steps>
      <Step title="Update server.properties">
        Open `server.properties` and set `online-mode` to `false` for an offline or mixed server, or `true` for a fully premium-only server.

        ```properties
        online-mode=false
        ```
      </Step>
      <Step title="Update config.yml">
        Open rLogin's `config.yml` and set `auth-mode` to match your server setup.

        ```yaml
        auth-mode: auto   # Recommended — handles both premium and cracked players
        ```

        Valid values are `auto`, `online`, and `offline`. Use `auto` for mixed servers. See the [config file reference](/configuration/config-file) for a full description of each value.
      </Step>
      <Step title="Restart the server">
        Restart your server fully to apply both changes. Running `/rlogin reload` is not sufficient for `online-mode` changes because that setting is applied by the Minecraft server itself at startup.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Is my players' data safe?">
    Yes. rLogin never stores passwords in plain text. All passwords are hashed using **BCrypt**, a widely trusted, slow-hashing algorithm specifically designed for secure password storage. Even if someone gained access to your database, they could not reverse the hashes back into plain text passwords.

    For maximum security, ensure your database server is not publicly accessible and keep your `config.yml` database credentials private. See the [database configuration guide](/configuration/database) for best practices.
  </Accordion>

  <Accordion title="Can I import accounts from AuthMe, nLogin, or another auth plugin?">
    Native import from AuthMe, nLogin, or other authentication plugins is not currently built into rLogin. Check the [Pyrelight Discord](https://discord.gg/pyrelight) — community members have created migration tools and scripts that may work for your setup.

    <Warning>
      Do not run AuthMe, nLogin, or FastLogin alongside rLogin. These plugins conflict with rLogin and will cause unpredictable authentication behavior. Disable or remove them before installing rLogin.
    </Warning>

    Always back up your database before attempting any migration.
  </Accordion>

  <Accordion title="Which server software does rLogin support?">
    rLogin supports **Spigot**, **Paper**, and **Purpur** running Minecraft **1.8 and above**. It does not support Vanilla, Forge, or Fabric servers, as those platforms do not provide the plugin API that rLogin requires.

    If you are running an unsupported server type, rLogin will not load. See the [installation guide](/installation) to verify your setup meets the requirements.
  </Accordion>
</AccordionGroup>
