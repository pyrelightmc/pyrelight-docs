If rLogin is not behaving as expected, this page covers the most common issues and how to resolve them. Work through the relevant section below, then restart or reload the plugin after making any changes. If you are still stuck after working through these steps, see [Getting More Help](#getting-more-help) at the bottom of this page.

<AccordionGroup>
  <Accordion title="Premium players are asked for a password instead of auto-logging in">
    Premium players should never see a password prompt. If they do, rLogin is not recognizing them as premium. Check the following:

    **1. Verify your `auth-mode` setting**

    Open `plugins/rLogin/config.yml` and confirm `auth-mode` is set to `auto` or `online`:

    ```yaml
    auth-mode: auto
    ```

    Setting `auth-mode: offline` forces all players through password authentication regardless of account type. See the [config file reference](/configuration/config-file) for all valid values.

    **2. Check `online-mode` in `server.properties`**

    For BungeeCord and Velocity networks, or mixed-mode servers, the backend server's `online-mode` must be set to `false`. Authentication is then handled by rLogin rather than the Minecraft server itself.

    ```properties
    online-mode=false
    ```

    **3. Verify Mojang session server connectivity**

    rLogin contacts `sessionserver.mojang.com` to verify premium players. If your server cannot reach that endpoint, premium authentication will fail. Test connectivity from your server host:

    ```bash
    curl -I https://sessionserver.mojang.com
    ```

    If the request times out or returns an error, contact your hosting provider or check your firewall rules to ensure outbound HTTPS traffic to `sessionserver.mojang.com` is allowed.
  </Accordion>

  <Accordion title="Plugin does not load / error in console on startup">
    If rLogin fails to load, you will see an error in your server console during startup. Follow these steps to diagnose the issue:

    <Steps>
      <Step title="Confirm you are using a supported server">
        rLogin supports **Spigot**, **Paper**, and **Purpur** running Minecraft 1.8 or above. It does not support Vanilla, Forge, or Fabric. If you are on an unsupported platform, rLogin will not load at all. See the [installation guide](/installation) for requirements.
      </Step>
      <Step title="Confirm the jar is in the correct folder">
        Make sure `rLogin.jar` is placed directly inside your server's `plugins/` directory — not in a subdirectory.
      </Step>
      <Step title="Check for conflicting authentication plugins">
        Running rLogin alongside **AuthMe**, **nLogin**, or **FastLogin** will cause conflicts and may prevent rLogin from loading or functioning correctly. Disable or remove any conflicting authentication plugins before starting your server.
      </Step>
      <Step title="Check your Java version">
        rLogin requires Java 8 or higher. Run the following to check your installed version:

        ```bash
        java -version
        ```

        If you are on an older version, update Java through your hosting panel or system package manager.
      </Step>
      <Step title="Read the full error message">
        Scroll through your server console or `logs/latest.log` to find the specific error rLogin printed. Error messages like `ClassNotFoundException` or `NoSuchMethodError` often indicate a version mismatch between rLogin and your server software.
      </Step>
      <Step title="Re-download the jar">
        A corrupted download can cause load failures. Delete the existing jar, re-download rLogin from the official source, and restart your server.
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="Config changes are not taking effect">
    If you edit `config.yml` or `messages.yml` and the changes do not appear in-game, try the following:

    **1. Reload the plugin**

    Run the reload command from your console or in-game:

    ```text
    /rlogin reload
    ```

    This re-reads both `config.yml` and `messages.yml` without restarting the server.

    **2. Restart the server**

    If `/rlogin reload` does not apply your changes, do a full server restart. Some settings (such as database connection settings) only take effect on startup.

    **3. Validate your YAML syntax**

    Malformed YAML will cause rLogin to silently fall back to default values or fail to load the config entirely. Common mistakes include:

    - Using **tab characters** for indentation (YAML requires spaces)
    - Missing colons after keys
    - Incorrect quote pairing

    Paste your `config.yml` into a YAML validator such as [yaml.me](https://yaml.me) to check for syntax errors before reloading.

    ```yaml
    # Correct YAML indentation uses spaces, not tabs
    database:
      type: mysql
      host: localhost
    ```

    For a full reference of every supported config key, see the [config file reference](/configuration/config-file).
  </Accordion>

  <Accordion title="MySQL connection error">
    If rLogin logs a database connection error on startup, verify every part of your MySQL configuration in `plugins/rLogin/config.yml`:

    ```yaml
    database:
      type: mysql
      host: localhost       # IP or hostname of your MySQL server
      port: 3306            # Default MySQL port
      name: rlogin_db       # Name of the database (must already exist)
      username: rlogin_user
      password: yourpassword
    ```

    Work through this checklist:

    - **Host and port** — Confirm the MySQL server is running on the host and port you specified.
    - **Database exists** — Log into MySQL and verify the database has been created: `SHOW DATABASES;`
    - **User permissions** — Confirm the MySQL user has `SELECT`, `INSERT`, `UPDATE`, and `DELETE` privileges on the rLogin database: `SHOW GRANTS FOR 'rlogin_user'@'localhost';`
    - **Firewall rules** — If your MySQL server is on a separate machine, confirm that port 3306 is open between the two servers.
    - **Remote connections** — If connecting to a remote host, ensure MySQL is bound to the correct network interface (not just `127.0.0.1`).

    <Tip>
      If you are unsure whether the credentials are correct, try connecting manually from the server using the MySQL CLI:

      ```bash
      mysql -h <host> -P <port> -u <username> -p <database>
      ```
    </Tip>

    See the [database configuration guide](/configuration/database) for the full list of supported options, including SQLite setup.
  </Accordion>

  <Accordion title="Players can move or interact before logging in">
    rLogin cancels player movement and interaction until they authenticate. If players are able to move freely before logging in, another plugin is likely overriding rLogin's event handling.

    <Steps>
      <Step title="Check the console for conflicts">
        Look for warnings in `logs/latest.log` about event priority conflicts or plugins cancelling the same events as rLogin.
      </Step>
      <Step title="Check for conflicting authentication plugins">
        Running **AuthMe**, **nLogin**, or **FastLogin** alongside rLogin will cause unpredictable behavior including movement not being blocked. Remove any other authentication plugins and test again.
      </Step>
      <Step title="Test with other plugins disabled">
        Temporarily disable other plugins one by one (or use a clean test server) to identify which plugin is interfering.
      </Step>
      <Step title="Check login-timeout">
        If `login-timeout` in `config.yml` is set very low, players may be kicked before they have a chance to log in, but if it is set to `0`, the timeout may be disabled entirely. Verify the setting is configured to a reasonable value (e.g. 60 seconds):

        ```yaml
        login-timeout: 60
        ```
      </Step>
    </Steps>
  </Accordion>

  <Accordion title="/rlogin unregister says the player was not found">
    Player names in rLogin are **case-sensitive**. If you run `/rlogin unregister steve` but the account was registered as `Steve`, the command will fail to find the account.

    Make sure you type the player's username with the exact capitalisation they used when registering. You can check the correct casing by looking at the player's name in-game, in your server logs, or directly in the database.

    ```text
    # Incorrect — wrong capitalisation
    /rlogin unregister steve

    # Correct
    /rlogin unregister Steve
    ```

    For a full list of admin commands and their syntax, see the [commands reference](/reference/commands).
  </Accordion>

  <Accordion title="Two players with the same username are causing conflicts">
    This occurs when a non-premium player uses a username that matches a premium Mojang account. Enable username-steal protection in `plugins/rLogin/config.yml` to prevent this:

    ```yaml
    prevent-username-steal: true
    ```

    With this option enabled, rLogin checks each non-premium player's username against Mojang's API on join. If the username belongs to a real premium account, the non-premium player is denied entry.

    After editing `config.yml`, run `/rlogin reload` or restart the server to apply the change.

    <Warning>
      If you disable `prevent-username-steal`, any cracked player can join using a premium player's username and potentially interact with their data. Keep this setting enabled unless you have a specific reason to disable it.
    </Warning>
  </Accordion>

  <Accordion title="Players are being kicked for too many failed login attempts">
    rLogin tracks failed login attempts to protect against brute-force attacks. If legitimate players are being kicked unexpectedly, check the `max-login-attempts` setting in `config.yml`:

    ```yaml
    max-login-attempts: 5
    ```

    Increase this value if players on slow connections or with typo-prone passwords are being blocked. To re-allow a player who has been locked out, use the force-login command from your console:

    ```text
    /rlogin forcelogin <player>
    ```

    This immediately authenticates the specified player without requiring their password, useful for locked-out admins or players experiencing repeated issues.
  </Accordion>
</AccordionGroup>
