All core rLogin settings live in `plugins/rLogin/config.yml`. This file is generated automatically the first time your server starts with rLogin installed — you never need to create it by hand. Every option is described below so you can tailor authentication behaviour to your server's exact needs.

<Note>
  Edit `config.yml` while the server is stopped, or run `/rlogin reload` after saving your changes so rLogin picks them up without a full restart.
</Note>

## Full Example Config

The following block shows a complete `config.yml` with realistic defaults and inline comments explaining each setting.

```yaml
# rLogin Configuration

# Authentication mode
# online:  only premium players (requires online-mode=true in server.properties)
# offline: only non-premium (cracked) players
# auto:    mixed — premium players are logged in automatically, others use a password
auth-mode: auto

# How long (in seconds) a player's session stays valid after they disconnect.
# Set to 0 to require a fresh login on every join.
session-timeout: 0

# Maximum failed login attempts before the player is kicked.
max-login-attempts: 5

# Time limit (in seconds) for a player to authenticate after joining.
# If they don't log in within this window they are kicked automatically.
login-timeout: 60

# Minimum and maximum password length enforced during /register.
min-password-length: 6
max-password-length: 32

# BCrypt hashing cost rounds. Higher values are more secure but slower to compute.
# Recommended range: 10–12. Avoid going above 14 on shared or low-powered hardware.
bcrypt-rounds: 10

# Prevent non-premium players from registering a username that matches
# an existing premium (Mojang/Microsoft) account name.
# Recommended: true — prevents impersonation attacks.
prevent-username-steal: true

# Optional spawn location for unauthenticated players.
# When enabled, players are teleported here immediately on join and
# returned to their original position after they authenticate.
auth-spawn:
  enabled: false
  world: world
  x: 0.0
  y: 64.0
  z: 0.0

# Database backend (see the Database page for full details).
database:
  type: sqlite  # sqlite or mysql
```

## Option Reference

### `auth-mode`

| Field   | Value                        |
| ------- | ---------------------------- |
| Type    | `string`                     |
| Default | `auto`                       |
| Options | `online`, `offline`, `auto`  |

Controls which players must authenticate with a password.

- **`online`** — requires `online-mode=true` in `server.properties`. All players are verified by Mojang/Microsoft; rLogin's password commands are not used.
- **`offline`** — all players are treated as non-premium and must register and log in with a password.
- **`auto`** — the recommended mixed mode. rLogin checks each connecting player's UUID against Mojang's API. Premium players are logged in automatically; everyone else must use `/login`.

---

### Session Settings

#### `session-timeout`

| Field   | Value     |
| ------- | --------- |
| Type    | `integer` |
| Default | `0`       |
| Unit    | Seconds   |

How long rLogin remembers a player's login after they disconnect. When a player rejoins within this window from the same IP address, they are authenticated automatically without typing their password again.

Set to `0` to disable sessions entirely and require a password every time.

#### `login-timeout`

| Field   | Value     |
| ------- | --------- |
| Type    | `integer` |
| Default | `60`      |
| Unit    | Seconds   |

The window (in seconds) a joining player has to run `/login` or `/register` before being kicked. Increase this value if players on slow connections are being kicked before the login screen appears.

---

### Login Attempt Limits

#### `max-login-attempts`

| Field   | Value     |
| ------- | --------- |
| Type    | `integer` |
| Default | `5`       |

The number of consecutive wrong passwords a player may enter before being kicked. Lowering this value makes brute-force attacks harder; raising it is more forgiving for players who mistype.

---

### Password Policy

#### `min-password-length` / `max-password-length`

| Field   | Value      |
| ------- | ---------- |
| Type    | `integer`  |
| Default | `6` / `32` |
| Unit    | Characters |

Enforce a minimum and maximum length when players run `/register`. rLogin rejects passwords outside this range and prompts the player to choose a valid one.

#### `bcrypt-rounds`

| Field   | Value     |
| ------- | --------- |
| Type    | `integer` |
| Default | `10`      |

The cost factor passed to BCrypt when hashing passwords. Each increment roughly doubles the time required to hash a password — and equally doubles the time required for an attacker to crack it offline.

<Warning>
  Values above `12` can noticeably slow down login on servers with many simultaneous joining players or on hardware with limited CPU resources. Test on your specific hardware before deploying a high value in production.
</Warning>

---

### Security

#### `prevent-username-steal`

| Field   | Value     |
| ------- | --------- |
| Type    | `boolean` |
| Default | `true`    |

When `true`, rLogin queries the Mojang API on registration and blocks non-premium players from claiming a username that belongs to a real premium account. This prevents a cracked-client player from impersonating a premium player who has not yet joined your server.

<Note>
  Leave this set to `true` unless you have a specific reason to allow it. Disabling it opens the door to impersonation on mixed (`auto`) servers.
</Note>

---

### Auth Spawn

#### `auth-spawn`

| Field   | Value            |
| ------- | ---------------- |
| Type    | `object`         |
| Default | `enabled: false` |

When `enabled: true`, rLogin teleports unauthenticated players to the coordinates you specify as soon as they join. After they successfully log in or register, they are teleported back to where they were (or to the server's default spawn if no prior position exists).

This prevents players from moving around the world before they authenticate. Configure the `world`, `x`, `y`, and `z` fields to point to a secure lobby or isolated spawn area.

---

### Database

#### `database.type`

| Field   | Value             |
| ------- | ----------------- |
| Type    | `string`          |
| Default | `sqlite`          |
| Options | `sqlite`, `mysql` |

Selects the storage backend rLogin uses to persist player accounts and session data. Set this to `mysql` and add the corresponding connection fields to switch to a MySQL server.

<Tip>
  See the [Database configuration page](/configuration/database) for full MySQL connection options, performance recommendations, and instructions on migrating between backends.
</Tip>

---

## Applying Changes

<Tip>
  Use `/rlogin reload` to apply any config changes at runtime instead of restarting the entire server. This reloads both `config.yml` and `messages.yml` in one command.
</Tip>

If rLogin encounters a problem parsing your edited file, it will log an error to the console and continue running with the previously loaded configuration so your server stays online.
