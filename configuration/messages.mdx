rLogin uses a `messages.yml` file located in `plugins/rLogin/` to define all in-game text shown to players. You can change every message — login prompts, error notices, success confirmations, kick reasons, and more — to match your server's language, tone, or branding, all without touching any code.

<Note>
  `messages.yml` is generated automatically on first run with default English messages. You only need to edit the values you want to change; rLogin falls back to its built-in defaults for any key that is missing from the file.
</Note>

---

## Color Codes

rLogin supports standard Minecraft color and formatting codes using the `&` prefix, as well as hex colors for servers running Minecraft 1.16 or later.

### Standard Color Codes

| Code | Color / Style |
| ---- | ------------- |
| `&0` | Black         |
| `&1` | Dark Blue     |
| `&2` | Dark Green    |
| `&3` | Dark Aqua     |
| `&4` | Dark Red      |
| `&5` | Dark Purple   |
| `&6` | Gold          |
| `&7` | Gray          |
| `&8` | Dark Gray     |
| `&9` | Blue          |
| `&a` | Green         |
| `&b` | Aqua          |
| `&c` | Red           |
| `&d` | Light Purple  |
| `&e` | Yellow        |
| `&f` | White         |

### Formatting Codes

| Code | Style         |
| ---- | ------------- |
| `&l` | **Bold**      |
| `&o` | *Italic*      |
| `&n` | Underline     |
| `&m` | Strikethrough |
| `&k` | Obfuscated    |
| `&r` | Reset         |

### Hex Colors (1.16+)

Use the `&#RRGGBB` format to specify any 24-bit color:

```text
&#FF5733Welcome to the server!
```

<Info>
  Hex color codes only render correctly for players connecting on Minecraft **1.16 or later**. Players on older clients will see the raw `&#RRGGBB` text instead of the intended color. If your server supports older clients, stick to the standard `&` color codes.
</Info>

## Annotated messages.yml

The following example shows every default message with inline comments explaining when each one appears.

```yaml
# Login prompt shown to non-premium players when they join.
login-prompt: "&eWelcome back! Use &f/login <password> &eto access the server."

# Registration prompt shown to new non-premium players on their first join.
register-prompt: "&eNew here? Use &f/register <password> <confirmPassword> &eto create your account."

# Shown to the player immediately after a successful /login.
login-success: "&aYou have been successfully logged in!"

# Shown to the player immediately after a successful /register.
register-success: "&aAccount created! You are now logged in."

# Shown when a player enters the wrong password with /login.
# %remaining% = attempts left, %attempts% = attempts made so far.
login-wrong-password: "&cIncorrect password. You have %remaining% attempts remaining."

# Kick message sent when a player fails to authenticate before login-timeout expires.
# %timeout% = the configured login-timeout value in seconds.
login-timeout: "&cYou took too long to log in. Please reconnect."

# Kick message sent when a player exceeds max-login-attempts.
# %attempts% = the number of failed attempts made.
max-attempts-reached: "&cToo many failed attempts. You have been kicked."

# Shown when the two passwords provided to /register do not match.
passwords-dont-match: "&cPasswords do not match. Please try again."

# Shown when the chosen password is shorter than min-password-length.
# %min% is replaced with the configured minimum length.
password-too-short: "&cPassword must be at least %min% characters long."

# Shown when the chosen password is longer than max-password-length.
# %max% is replaced with the configured maximum length.
password-too-long: "&cPassword must be no longer than %max% characters."

# Shown when a non-premium player tries to register a username already
# claimed by a premium (Mojang/Microsoft) account.
username-taken: "&cThat username belongs to a premium account and cannot be used."

# Shown when a player tries to run /login but is already authenticated.
already-logged-in: "&cYou are already logged in."

# Shown when a player runs /login but has not registered yet.
not-registered: "&cYou don't have an account yet. Use /register to create one."

# Shown after a player successfully changes their password with /changepassword.
password-changed: "&aYour password has been changed successfully."
```

## Message Key Reference

| Key                  | When It Appears                                                      | Supported Placeholders              |
| -------------------- | -------------------------------------------------------------------- | ----------------------------------- |
| `login-prompt`       | Shown to a non-premium player when they join and need to log in      | `%player%`                          |
| `register-prompt`    | Shown to a new non-premium player who has not yet registered         | `%player%`                          |
| `login-success`      | Shown immediately after a successful `/login`                        | `%player%`                          |
| `register-success`   | Shown immediately after a successful `/register`                     | `%player%`                          |
| `login-wrong-password` | Shown when a player enters an incorrect password                   | `%player%`, `%attempts%`, `%remaining%` |
| `login-timeout`      | Kick message when the player runs out of time to authenticate        | `%player%`, `%timeout%`             |
| `max-attempts-reached` | Kick message when failed attempts exceed `max-login-attempts`      | `%player%`, `%attempts%`            |
| `passwords-dont-match` | Shown when `/register` passwords do not match                      | `%player%`                          |
| `password-too-short` | Shown when the chosen password is below `min-password-length`        | `%player%`, `%min%`                 |
| `password-too-long`  | Shown when the chosen password exceeds `max-password-length`         | `%player%`, `%max%`                 |
| `username-taken`     | Shown when a cracked player tries to claim a premium account's name  | `%player%`                          |
| `already-logged-in`  | Shown when an already-authenticated player runs `/login`             | `%player%`                          |
| `not-registered`     | Shown when a player runs `/login` but has no registered account      | `%player%`                          |
| `password-changed`   | Shown after a successful `/changepassword`                           | `%player%`                          |

## Placeholders

Use these placeholders inside message strings — rLogin replaces them with live values at runtime.

| Placeholder   | Replaced With                                                      | Example Keys                                    |
| ------------- | ------------------------------------------------------------------ | ----------------------------------------------- |
| `%player%`    | The player's in-game name                                          | `login-prompt`, `login-success`                 |
| `%min%`       | The value of `min-password-length` from `config.yml`              | `password-too-short`                            |
| `%max%`       | The value of `max-password-length` from `config.yml`              | `password-too-long`                             |
| `%attempts%`  | The number of failed login attempts the player has made            | `login-wrong-password`, `max-attempts-reached`  |
| `%remaining%` | The number of login attempts remaining before the player is kicked | `login-wrong-password`                          |
| `%timeout%`   | The configured `login-timeout` value in seconds                    | `login-timeout`                                 |

**Example using placeholders:**

```yaml
login-wrong-password: "&cWrong password, &e%player%&c. &f%remaining% &cattempts remaining."
max-attempts-reached: "&cYou have been kicked after &f%attempts% &cfailed attempts."
password-too-short: "&cPassword too short! Minimum length is &f%min% &ccharacters."
login-timeout: "&cYou had &f%timeout% &cseconds to log in. Please reconnect and try again."
```

## Tips for Customising Messages

<Tip>
  Run `/rlogin reload` after saving `messages.yml` to apply your changes immediately without restarting the server.
</Tip>

<Tip>
  Use `&r` at the end of colored segments to reset formatting and prevent color from bleeding into adjacent text. For example: `"&cError: &r%player% is not registered."`.
</Tip>

<Note>
  If you delete a key from `messages.yml`, rLogin uses its built-in English default for that message. You don't need to keep keys you haven't changed — only the ones you've customised need to be present in the file.
</Note>

### Multi-Language Servers

If your community speaks multiple languages, consider creating language-specific `messages.yml` templates and swapping them in via a management script or a server panel. rLogin does not natively support per-player language selection, but all messages can be freely translated into any language supported by Minecraft's Unicode rendering.

<Info>
  Some special characters (for example, accented letters in French, German, or Spanish) must be entered as their literal Unicode characters or encoded in UTF-8. Ensure your text editor saves `messages.yml` with **UTF-8 encoding** to avoid garbled characters in-game.
</Info>
